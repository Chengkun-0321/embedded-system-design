  • `npm start` → 跑開發伺服器 (http://localhost:3000)
  • `package.json` 中 `proxy` 指向 `http://localhost:4000`，以方便開發時跨域轉發
• root (HW2/)
  • 用 `concurrently` 同時啟動前後端
  • `npm run dev` → 開發模式：前端+後端一起跑

備註：

- `web-mgt/src/pages/page1.js` 包含搜尋 UI，開發模式時 React StrictMode 可能會導致某些 useEffect 觸發兩次（僅開發時）。

快速啟動（在 Mac / zsh）
1) 安裝相依套件（在專案根目錄）
   npm install

2) 若要同時啟動前後端（concurrently）
   npm run dev

3) 單獨啟動後端
   cd web
   npm run dev   # 或 npm start（正式模式）

4) 單獨啟動前端
   cd web-mgt
   npm start     # 開發伺服器在 http://localhost:3000

常見錯誤與處理建議
- Proxy 錯誤 (ECONNREFUSED / ECONNRESET)
  • 症狀：前端 console 顯示 "Could not proxy request /api/... from localhost:3000 to http://localhost:4000"。
  • 原因：後端伺服器未啟動或在不同埠，導致 proxy 無法連線。
  • 處理：確認 `web` 在埠 4000 正常啟動；或檢查 `web-mgt/package.json` 的 `proxy` 是否正確。

- React 在開發模式呼叫 API 兩次
  • 症狀：後端 log 看到同樣的 GET 請求出現兩次（例如 `/api/username`）。
  • 原因：React 18 在開發環境下啟用 `StrictMode`，會做「掛載 → 卸載 → 再掛載」以檢測副作用，因此在 `useEffect(..., [])` 中的副作用會被執行兩次（僅開發）。
  • 建議：
    - 在開發短期可移除 `React.StrictMode`（`src/index.js` 或 `src/App.js`）以避免雙重呼叫，但 production build 不會有此行為。
    - 或在呼叫 API 的元件中使用 `useRef` 作一次性保護：
      const didFetch = useRef(false);
      useEffect(() => {
        if (didFetch.current) return;
        didFetch.current = true;
        // fetch...
      }, []);

- /api/search 找不到路由
  • 症狀：前端呼叫 `/api/search` 但後端回 404 或沒有回應。
  • 建議：在 `web/app.js` 中新增 `/api/search` 路由，並以 `web/services/searchService.js` 或直接讀 `data/0_20000.csv` 來回傳搜尋結果範例。

- `web-mgt/package.json` : dev server proxy 設定 (proxy -> http://localhost:4000)
